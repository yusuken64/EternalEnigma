# Encounter generation and host integration

Campaign generator 11 assigns all eleven encounter archetypes in every campaign. Six seeded regional landmarks host city, woods, cave, prison, ambush and boss content; four distinct capability payoffs host puzzles. The bridge occupies its own deliberate entry marker and seals one existing progression boundary until completion. Capability prerequisites remain on that boundary. All generated keys now require dungeon completion. Reset Floor is derived from completion of `repeatable-0`.

Use `CampaignContext.RunPlan(id)` and its floor options, rather than deriving encounter length or combat difficulty from the floor number. Existing dungeon ranges are unchanged. Their final dungeon's last combat floor is a large Demon King arena. New encounters use playable floors throughout; city, woods, cave and prison lengths are 2/2/3/3/4 by tier.

`DungeonFloor` provides an objective, stable objective-enemy identities, puzzle objects, recovery stashes, exits and solution witnesses. `DungeonObjectiveProgress` tracks required deaths and reinforcements and supplies the shared exit condition. Runtime hosts remain responsible for checking that condition before any transition and rejecting conversion, arbitrary despawning or damage to protected targets.

`PuzzleState` is the shared action model. Only controlled-character entries toggle lights; cardinal pushes move exactly one boulder. Target movement uses a fixed east/north/west/south tie break. Hosts synchronize character switches with `SetPlayerPosition`, observe skill displacement with `ObservePlayerEntry`, and move targets using `NextEnemyPosition` followed by `ObserveEnemyPosition`. Do not observe a light entry twice after `TryMove`. Legal inverse pushes construct Sokoban boards; reversible entry transitions construct light boards. Stored move witnesses replay through this same model. Target witnesses use bounded search against the same movement policy. Resetting host state must include inventory, equipment, gold, experience, statuses, random state and escrow, not merely `PuzzleState`.

`OverworldGrid.LocationFootprints` reserves 5×5 external miniatures and 7×7 woodland miniatures before decoration. Their cells preserve Core terrain authority: presentation must keep the entrance, roads and approaches unobstructed. `Grid.Pickups` provides three persistent identities per region, a kind, position and deterministic roll. Hosts select from sorted eligible existing item definitions. `CampaignContext.TryCollectPickup` calls the host's inventory acceptance function first and records the pickup only on success; `CampaignSnapshot.CollectedPickups` is part of explicit-save state.

CLI `--dungeon <encounter-location-id> --floor <n> --output <directory>` exports the run objective, objects, stable identities, witnesses and floor fingerprint alongside SVG previews. The console dungeon explorer displays and operates puzzle objects, simulates required enemy defeats with Enter beside them, and gates stairs on objective completion. R resets puzzle floors. JSON exports remain diagnostics, not a save format.

Generation changes apply to new campaigns. Old save slots retain their data and follow the existing fingerprint-mismatch policy; nothing migrates or deletes them automatically. Core validation covers seeded generation and abstract progression. Unity party behavior, escrow identity, movement skills, boss abilities, reset transactions and visual/WebGL acceptance require their host integration tests.
