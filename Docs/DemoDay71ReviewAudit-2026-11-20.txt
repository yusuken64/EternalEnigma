Implementation follow-up: text containment and held movement (2026-11-20)
The findings above describe the initial audit. The following work resolves its
text-fit failure and stale test blockers, plus the Full Control overflow shown
in the user's later screenshot. It does not close the separate design requests
for inventory capacity, shared storage, dungeon density or progression balance.

Why the Full Control button escaped the old audit
The old check measured rendered glyphs against the text rectangle and enclosing
panel bounds. A decorative sprite's rectangle includes its bevel and lower
shadow, which are not usable caption space. The check also did not consistently
follow Button.targetGraphic when the background was a child object rather than
an ancestor of the label. Consequently this caption could pass geometry checks
while hanging below the wooden face. Passing that check was insufficient visual
evidence; the audit needed to measure the actual decorative face.

Implemented corrections
- Wooden buttons and heading ribbons fit captions inside the painted face,
  accounting for nine-slice scaling. Full Control has enough height for normal
  and pending "next round" captions at every tested aspect ratio.
- The inventory picker has room for its heading and two-line footer. Status
  badges use compact frames instead of wood bevels that consume their text area.
- Header buttons retain their border padding and clear the resource strip.
  Cloned toolbar buttons discard margins calculated for the source button size.
- The event feed reserves a header row and reflows beside open menus. Its History
  button's painted background stays clear of the dock. Closing a menu restores
  the authored layout. An idle-performance test verifies no repeated formatting.
- A fresh movement press takes one step promptly. Release clears repeat state,
  including diagonal-release grace. Held walking continues across tween/turn
  boundaries without an idle frame; extra automatic wait actions preserve the
  walk animation. Two-action heroes retain the same manual walking cadence.
  The earlier tree-only corner rule and strict attack/sight corners remain.
- Stale status-discovery, permanent-Frailty removal, row-index and header-layout
  assertions now test current behavior. The previously blocked UI interactions
  and exhaustive status popup sweep were rerun successfully.

Stronger audit coverage
TextLayoutAudit now follows the actual button graphic, measures painted caption
faces, checks button backgrounds against screen/mask bounds, and detects UI
covered by an open gameplay dock. Intentional partial scrolling rows and the
terminal world behind dialogs retain their specific exceptions. The focused
scroll row must remain fully reachable. Failure captures are saved before layout
assertions so a future failure includes a screenshot. Header tests separately
reject truncated captions and measure rendered glyphs, rather than treating
unused font line-box padding as visible overflow.
